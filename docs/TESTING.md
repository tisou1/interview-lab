# 测试与验收

## 自动检查

```sh
pnpm typecheck
pnpm test
pnpm build
pnpm exec playwright install chromium
pnpm test:e2e
```

E2E 默认启动 4173 端口的 Vite 服务器，在 Chromium 桌面视口和 Pixel 7 移动视口运行。可通过 `PLAYWRIGHT_CHANNEL=chrome` 使用已安装的 Google Chrome。失败截图、trace 和成功的视觉截图保存在 `test-results/`。

## 单元与组件测试

- 实际 115 道题的编号完整性、题干代码与无标题答案保留。
- Markdown 新增第 116 题、混合 HTML/Markdown、代码中的伪标题、HTML 安全过滤和解析错误定位。
- 分类均衡去重抽题、弱题优先、题量不足、联合筛选。
- 复习间隔、连续掌握重置、旧数据基线、历史报告改评。
- 幂等提交、草稿重载、导入导出、重复记录拒绝、损坏备份和 quota 错误提示。
- 按当地日期聚合，跳过/未回答不计入作答量。
- 答案初始隐藏、独立分层、输入框快捷键不误触发和面试期间答案入口隐藏。

## 浏览器流程

1. 搜索 React → 打开题目 → 收藏/草稿 → 展开答案 → 自评 → 刷新恢复 → 前进后退。
2. 开始 5 题练习 → 草稿 → 刷新 → 自评后下一题 → 跳过 → 完成。
3. 模拟面试 → 不会/待复查 → 刷新恢复截止时间 → 交卷 → 改评 → 错题列表。
4. 过期场次刷新后自动交卷，重复刷新不产生重复记录。
5. 导出 → 清空确认 → 导入确认 → 草稿、自评、主题与统计恢复。
6. 桌面/移动首页、题目与路线无页面横向溢出；导航抽屉和全屏草稿支持焦点恢复。
7. 临时追加第 116 题，验证 watcher 将其加入题库、自评和统计，finally 恢复原始 Markdown。此测试单 worker、只运行一次。

## 交付前人工检查

- 检查桌面与移动截图中题干、代码、按钮、图表和深浅主题。
- 静态服务器直接访问 `/questions/1` 和不存在的 `/mock/report/example`，刷新后应进入对应页面或应用空状态。
- 在浏览器模拟 Slow 4G 与 CPU throttling，确认首页不请求全部答案，搜索/自评仍能响应。
- 真机 Android 的字体、软键盘和性能需在目标设备继续验证，移动视口模拟不能替代真机。
